Concern

We already have users

Ripping out the live UI is risky

The team has not fully integrated the prototype. Engineering is unsure about overriding the current live UI. That hesitation is correct. A hard cutover is a product risk, not a design preference.

Live has users

They already know today’s screens. We do not get to pretend this is a greenfield app.

Prototype is not integrated

Until it is, “replace live” is a leap, not a ship plan.

So we need another way

Not a big-bang override. A way people can move when the new experience is actually better.

flable.ai
Proposal · not committed engineering

Writesonic-style · smart AB

Let people switch. Prompt them. Do not force it.

Onboarding

Offer the new UI

At first-run, invite them to try the new experience. They can stay on live.

Notifications

Ask again, later

A quiet prompt after they are in: the new UI is ready, you can switch back.

In product

This is better there

“Try the new UI — you can do this here.” In context, while they are already working.

For this to work I have to make the prototype a guided product — educational at every point — or the switch will fail. Are we open to opt-in new UI rather than a big-bang override?
