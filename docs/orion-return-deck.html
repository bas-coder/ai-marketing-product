Proposal · not committed

Concern, then an idea

Do not rip out live UI. Let people opt in.

Problem

Live already has users

Engineering is right to be unsure about overriding the current UI. A hard cutover is risky.

Pattern

Writesonic-style switch

They shipped a new UI. Users chose to switch. Prompts at onboarding, in notifications, and in the product: “try the new UI — you can do X here.”

Ask

Opt-in, not a big bang

Are we open to an opt-in new experience instead of replacing live for everyone?

flable.ai
Design implication

If we go this way

The new UI has to teach itself

  • I will need to really improve the prototype — not just prettier screens.
  • Educational, informative guidance at every point, so the product explains itself.
  • Prompts while they work: this is better in the new UI, and you can switch back.
  • If the new experience does not teach, the switch fails. That is on design, not on a flag.

This is an idea for the team. Not engineering work until we agree.
